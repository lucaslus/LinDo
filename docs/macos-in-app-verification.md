# macOS 应用内登录与验证

登录、站点验证和 JSON / 附件 / 上传请求共用一个 WKWebView 与持久 WKWebsiteDataStore。WebKit 在 AppKit 主线程运行，通过异步 JNA 回调与 Kotlin 通信；不启动 Chrome / Edge，不开放本机调试端口。

验证面板附着在 Lindo 主窗口，原帖子及阅读位置保留。完成验证后收起面板，由已有的恢复回调重试失败的读取；不会自动重放提交。已登录账号验证时不再次发出登录状态回调。网页账号与 App 账号不符时不静默切换。

使用 HTML 页面承载站点验证，不把 session/current.json 等 API 作为落地页。顶层导航限制与网页内部 iframe 导航分开处理，后者交给 WebKit 的同源、沙箱和 CSP 机制；不能把 about:srcdoc / blob 等子页面一概拦截。验证控件保留网站原貌，不自动点击或伪造验证结果。

界面只保留关闭、域名和刷新；加载时使用小型进度指示。取消验证不退出账号，也不清理会话。退出账号会清理 Lindo 自己的 WebKit Cookie，Safari / Chrome 的个人数据不受影响。

## 验证记录（2026-11-16，build 58）

- 原生隔离测试使用 nonPersistent store：Cookie 往返、隐藏后保留、异步 JS 结果、取消状态、退出清理、拒绝非站点顶层命令。
- Kotlin 测试覆盖授权 URL 边界、API 到 HTML 验证页映射及 OTP 一次性兑换回归。
- Mac release 构建与签名校验通过；Android 编译通过。
- 实机观察：最初内嵌页面出现持续 Verifying；调整子页面导航与 HTML 落地页后，重启可加载首页，连续打开两篇帖子可显示正文与回复。
- 本次没有再次出现人工勾选，因此人工挑战通过后的完整回程尚未实测。不能据此承诺所有网络环境下 Cloudflare 均不再挑战。

## build 59：恢复判定与超时修复

- 从运行中的 build 58 读取到最后阶段为 `session-status-429-challenge-true`。这是额外的会话检查被站点挑战，不足以证明原帖子接口仍不可用。
- 普通验证固定检查触发验证的原始只读接口；不再以 `/session/current.json` 作为所有场景的完成条件。只有登录或确实重新登录后才核对账号身份。
- 内部探测不会覆盖原始受阻 URL；API 未恢复时按约 10 秒间隔探测，不刷新或切走用户正在完成的验证页面。
- 以接口的实际 JSON 响应作为恢复证据，不要求挑战 DOM 容器消失。普通权限/资源不存在响应交回原页面处理。
- 原生回调超时转为普通操作失败，不能取消页面协程并跳过加载状态清理；真正的用户取消仍传播。非 JSON JavaScript 返回值也必须完成错误回调。
- 新增阶段日志，仅记录路由、状态码与阶段，不记录 Cookie、请求参数或响应正文。
- Cloudflare 为什么挑战该接口，需要站点侧规则/事件日志才能确定；此修复不承诺第三方站点永不要求人工验证。
