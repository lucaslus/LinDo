# Lindo 设计语言：克制、内容优先的社区阅读界面

记录日期：2026-11-15。代码基线：main / 6861e14（build 52）。

本规范提炼自当前公共 UI 实现、用户截图及已经明确的偏好，不是重新设计方案，也不是某个系统组件库的照搬。标为“建议”的内容尚未全部落实；本文不代表逐页真机视觉验收。

## 1. 风格定义

**以阅读为中心，用排版建立层级，用轻分隔组织内容，用少量主题色表达操作与状态。**

可以称为“克制的内容型界面”。它不是极端冷淡、无图标的纯文字界面，也不是大卡片、大按钮、渐变背景组成的展示页。亲和力主要来自真实头像、零度娘和社区内容；应用外壳保持安静。

稳定的特征：

- 首页与帖子连续铺开，列表行和楼层不各自套一张悬浮卡片。
- 信息密度适中偏紧凑，但保留可读行距和清晰对齐。
- 中性色承担大部分画面，主题色只点亮少量重要位置。
- 主要内容优先，辅助信息弱化，低频设置按需展开。
- 操作直接，反馈靠近操作发生处，尽量不打断阅读。
- 全端共享视觉语言与行为，宽屏通过分栏和宽度约束适配。

“没有 AI 味”不是可测量的技术指标。这里对应的是可执行的约束：不堆装饰，不写空泛说明，不把所有内容卡片化，不凭空增加步骤，不为不同页面另造一套风格。

## 2. 先选结构，再选样式

设计新功能按以下顺序判断：

1. 用户现在要读内容、改设置、做操作，还是处理异常？
2. 哪一项是这一步必须看见的信息？哪一项可以按需出现？
3. 现有页面能否就地承载？能则不新开页、不加弹层。
4. 按数据类型选控件，而不是先决定用按钮或卡片。
5. 用对齐、间距、文字层级完成分组，再判断是否真的需要底色或边框。
6. 补齐等待、失败、取消、恢复和大字号状态。
7. 检查窄屏、宽屏、浅色、深色和不同主题色，而不是另做平台风格。

## 3. 页面与阅读

| 场景 | 默认方式 | 应避免 |
| --- | --- | --- |
| 首页、通知、账号列表 | 连续列表、轻分隔、固定对齐；选中使用低对比底色或强调色 | 每行独立圆角卡片、重复阴影 |
| 帖子与回复 | 正文为主，头像识别人，楼层/时间在稳定尾部位置 | 元数据挤压正文、楼层随昵称漂移 |
| 回复关系 | 小头像、名字、必要摘要；点击定位并短暂高亮，可回到原处 | 大块重复引用、装饰性标题和重边框 |
| 图片 | 保持比例，合理预览尺寸，按需打开原图 | 长图撑满阅读区域；额外文件名、宣传标题和图片外框 |
| 引用、代码、链接预览 | 在正文中明确表示内容类型，可用轻底色和小圆角 | 因“少圆角”而取消必要的内容边界 |
| 设置 | 分组行，默认仅显示名称与当前值；低频选项在行下展开 | 将所有选项常驻；为很小的设置单独新建页面 |
| 关于、登录 | 可以集中展示品牌和零度娘；功能文案简短 | 同时重复品牌名、社区客户端说明和宣传口号 |
| 宽屏 | 保持同一控件体系，适当分栏、限制表单与正文宽度 | 简单拉宽全部控件；桌面端另造视觉语言 |

阅读上下文属于功能：展开、验证、失败重试、返回后，尽量保留滚动位置、草稿和当前选择。一次辅助操作不应让用户重新寻找刚才在读的内容。

## 4. 圆角与容器：有用途才使用

用户的偏好不是“禁止圆角”，而是**少容器、少嵌套、选择性圆角**。

当前公共 tokens 为 6 / 10 / 14dp；实际实现另有 4、7、8、12、16dp 等局部值。下表是后续收敛方向，不是声称代码已统一。

| 对象 | 建议 |
| --- | --- |
| 页面、普通列表行、帖子楼层 | 平面铺开，不加卡片轮廓 |
| 标签、紧凑选择、轻提示 | 小圆角，优先向 6dp 层级收敛 |
| 输入区域、引用、代码等内容容器 | 视用途使用约 6–10dp，不重复套框 |
| 真正的弹层 | 一个外层边界；优先约 10–14dp，并按承载方式判断 |
| 头像、反应气泡、搜索、悬浮导航 | 圆形或胶囊是合理的形态例外 |
| 应用图标、系统窗口、第三方网页 | 遵守其自身规范，不机械套用上述半径 |

圆角值不是越小越专业。关键是同一处是否同时出现“大圆角外壳 + 大圆角内卡片 + 胶囊按钮”，以及这些容器是否都承担了真实用途。

玻璃、渐变与高光集中用于悬浮导航这类有明确层次作用的区域，不扩散到设置行、正文、验证状态和普通按钮。

## 5. 文字、颜色、图标

### 文字

当前 tokens：展示标题22、标题17、主信息16、正文15、辅助14、元信息12.5、注释12sp。实际页面存在场景差异：首页标题16sp / SemiBold，阅读正文有16sp的实现，关于品牌名26sp。不能把 token 表误当成全局已统一的事实。

后续原则：

- 正文正常字重，列表标题适度加重；粗体只建立层级，不铺满页面。
- 同一语义优先复用字号、字重与行高，避免按截图逐处添加零碎数值。
- 元信息弱化主要靠层级和颜色，不靠缩到难读。
- 五档字体按 80 / 90 / 100 / 110 / 120% 等步长变化；与系统字号共同作用。弹层也须生效，避免重复缩放。
- 长姓名、邮箱等上下排布或允许换行，不能挤压尾部操作。关键按钮文案不能拆成两行。
- 视觉紧凑不等于固定高度：大字号应允许换行或增加高度。

### 颜色

- 中性背景、主要文字、次要文字、细分隔线构成基础层次。
- 主题色用于选中项、主操作、开关/滑块激活态、未读标记和定位反馈；不把整页染成主题色。
- 品牌字标保留自身识别色；分类、徽章、用户内容保留语义与原始颜色，不强行全部主题化。
- 错误/破坏性操作使用语义色。等待、站点验证不默认渲染成红色警报。
- 选中不能只靠颜色：配合勾选、下划线、控件位置或无障碍选中语义。
- 浅深色使用语义 palette，而不是把深色截图简单反相。

### 图标与品牌

- 常规操作以一致的线性图标为主，按状态使用适量实心或强调色。
- 图标帮助识别；含义不明确的操作应有简短标签，不能只为了简洁而隐藏含义。
- 零度娘集中在品牌入口、登录、关于与少量确有帮助的空状态。加载每一步、每个弹窗不都加吉祥物。
- 原生托盘使用零度娘单色轮廓；不是将彩色头像缩得很小。

## 6. 表单控件选择

| 数据/任务 | 控件与展示规则 |
| --- | --- |
| 开/关 | Switch；整行可点，状态立即可见 |
| 有顺序的五档字号 | 离散滑块；拖动局部预览，松手应用全局，避免页面边拖边跳 |
| 少量互斥模式 | 紧凑单选/分段；图标与短文字同行，不做大块上下按钮 |
| 主题色 | 小色点 + 选中环/勾；不为每个颜色分配大卡片 |
| 图标与其底色 | 在同一图标选择流程中调整，避免在设置首页拆成两个相关入口 |
| 长列表选择 | 有当前值的入口，进入必要的选择面板；需要时提供搜索 |
| 资料字段 | 标签与内容有明确层级，长内容放下方；可编辑项有明确入口 |
| 多账号 | 头像 + 名字 + 账号标识；当前账号轻强调并带选中语义，点击切换 |
| 执行动作 | 按钮/文字操作；不要用选项控件伪装动作 |

折叠行显示“标题 + 当前值 + 展开指示”；展开后选项直接出现在行下。不要再重复一遍标题与解释。只有操作后果不明显时才增加一行必要说明。

**视觉尺寸与命中区域分开。** 当前紧凑选项可见图标很小，但设置选项保留48dp命中区域；后续触控入口以44–48dp为检查基准，不能因缩小外观而制造难点的小按钮。窄屏放不下时换行或滚动，避免压缩字号。

## 7. 操作、反馈与文案

- 导航用行/图标；常规操作用轻按钮；实心强调按钮保留给明确的主要提交或登录动作。
- 已经点了“验证”，下一步直接承载验证，不再弹“继续验证”。普通设置立即应用，不额外保存确认。
- 删除、移除等有明显后果的动作可保留一次确认，说明真正影响范围，不连环确认。
- loading 位于原操作附近，不遮盖已有内容；处理中防止重复触发。
- 出错保留草稿和原内容，提供就地重试。成功通常通过结果变化表达，不每次弹窗庆祝。
- 动画解释状态：展开/收起、定位高亮、未读淡出；不加与操作无关的弹跳或持续装饰动画，并尊重关闭动效的设置。
- 文案采用“对象/结果 + 必要动作”，例如“添加账号”“清理缓存”“验证”“重试”。不用“当前使用”重复说明已高亮的当前项。
- 不用可爱话术掩盖故障，也不把 Cookie、cURL、诊断日志等实现细节放进正常用户路径。
- 精简不能损害准确性：验证中应表达验证状态，不把所有网络步骤都写成“连接中”。

## 8. 本次验证容器修订方向

去掉设计图中的“连接确认”标题和对应品牌介绍区，也去掉包住网页的第二层圆角卡片。

build 53 已将单层承载面板实现为公共组件 `VerificationPageSurface`，Android 原生 WebView 接入该组件；工具栏使用真实域名、关闭、展开和刷新，网页加载使用细进度条。面板在可用高度不足600dp或字体倍率超过1.3时使用完整高度，也可手动展开。普通登录与浏览页面仍使用完整高度。macOS 当前浏览器会话适配器并非嵌入式 WebView，此次未将其替换；不能将公共组件的存在表述为 macOS 已拥有同样的内嵌验证面板。

建议结构：

1. 原阅读页保留；用户点“验证”后直接进入应用内网页承载层。
2. 顶部仅保留紧凑工具栏：关闭、低强调的真实域名，必要时提供重载。不放“连接确认”大标题，不重复网页内部标题。
3. 工具栏下直接呈现完整站点验证页面，不另加内卡片、装饰性边距或我们自己的模拟复选框。
4. 半屏能完整容纳时使用单层面板；内容过高则扩大或全屏，不能为了半屏造型裁切验证内容。窄屏/大字号尤其检查这一点。
5. 加载反馈放在工具栏的细进度条或原状态行，不再开“正在验证”弹窗。以真实验证状态驱动，避免无期限假 loading。
6. 验证成功后自动关闭并恢复原操作；失败在同一承载层给出重试/退出，不反复弹层。是否重发写操作需确认之前未成功，防止重复发布。

应用能控制的是承载层和恢复流程。站点验证页面的标志、颜色、复选框和必要点击由站点决定；不能承诺一定只需一次点击，也不能用我们的按钮替代其必要的人为确认。该限制不应变成产品界面中的大段说明。

## 10. 设计与代码评审清单

- 第一眼看到的是内容，还是围住内容的装饰？
- 是否能去掉一层容器、一个重复标题或一句无用说明？
- 圆角、底色、边框分别承担什么用途？有没有重复表达？
- 控件是否匹配数据类型？视觉缩小后是否仍容易点击？
- 默认状态是否只显示必要信息与当前选择？
- 是否只用少量主题色表达选中和主操作，且有非颜色状态提示？
- 长文本、五档字号、弹层字号和窄屏是否仍然对齐、可读？
- 等待、失败、取消后是否保留内容、草稿和位置？
- 一次意图是否引出了多次相同确认？
- 两个平台是否共享同一设计，只在布局和系统能力上适配？
- 零度娘是否出现在有品牌意义的位置，而非充当任意装饰？
- 是否直接复用了已有组件，而不是再创建一套相似样式？

## 11. 后续任务可复用的设计说明

> 沿用 Lindo 当前克制、内容优先的设计语言。普通列表和阅读内容平面铺开，以排版、留白和轻分隔建立层级；圆角按用途使用，避免卡片套卡片。中性色为基础，少量主题色表达选中与主操作。设置默认显示当前值，按需在原处展开，依据数据类型选择开关、滑块或紧凑单选。保留有意义的图标，控件视觉紧凑但命中区域充足。文案简短直接，反馈就地展示，保留阅读位置和草稿，避免重复确认。零度娘用于必要的品牌场景。全端共用组件和交互，按窗口宽度适配，不另造平台风格。以现有代码为依据，发现不一致时先列出，不把历史遗留细节当成新规范。

### 交互行的边界（build 56）

- 页面外边距与行内边距分别处理：悬停/按下背景内部也必须留白。账号页保持原有 20dp 内容对齐线，改由外层 4dp + 行内 16dp 组成。
- 平铺操作行共用 `RowInteraction.kt` 的悬停、按下、键盘焦点反馈。背景保持平直、低对比，不为 hover 新增卡片或大圆角；状态在绘制阶段读取，避免整条内容因 hover 重新组合。
- 可见选项较小时可以保留 48dp 触摸范围，但反馈绘制在可见选项内部，不能出现内圆外方的第二块底色。
- 账号的头像、文字与当前勾选属于同一选择区域；移除操作独立。
- 统计只展示服务端提供的字段。累计访问使用 `days_visited`；社区分数使用官方 `gamification_score`，不等同于 Credit 余额。加入天数按注册 UTC 日期计算并包含注册当天。缺失值不当作零；累计访问不能反推连续访问。
- 数据导出沿用 Discourse `user_archive` 服务端作业，单次提交，完成后通过站内私信下载。每日限额和异常不触发自动重试；逐日记录可用于后续连续访问分析。
