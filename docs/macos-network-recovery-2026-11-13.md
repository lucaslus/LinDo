# macOS 限流恢复与 Cloudflare 调查

## 已落实的行为

- 普通 HTTP 429：前台读取保留 loading，默认等待 2 秒，再自动重试一次。存在 `Retry-After` 时按秒数或 HTTP 日期执行，不提前重试。
- 全应用共享冷却截止时间。相同读取合并；冷却后的恢复请求串行进入，第一次恢复仍为 429 时，不让其余等待者分别启动重试循环。
- 后台请求在冷却期间不发送，也不排队自动重试。离开页面或取消刷新会取消等待；取消旧刷新不会误取消仍有效的新刷新。
- 服务端要求等待超过 10 秒时，不让页面无限 loading；返回“稍后再试”，仍保留服务器冷却时间。新的主动操作也不能提前绕过冷却。
- 带 Cloudflare 挑战标记的 429 不进入普通限流重试。验证期间暂停应用读取，验证窗口自身也遵守限流。
- 另一个请求成功、手动刷新、验证完成，都不会提前清除 macOS 的限流截止时间。
- 自动恢复只用于 GET/HEAD，不自动重放发帖、回复、上传等写操作。策略现已由 macOS 和 Android 启动启用；Android 保留原 WebView 登录、验证与页面交互。

## 官方资料与判断边界

1. [挑战识别](https://developers.cloudflare.com/cloudflare-challenges/challenge-types/challenge-pages/detect-response/)：优先识别 `cf-mitigated: challenge`，而非只看 403/429。挑战响应是 HTML，不是预期 API JSON。
2. [挑战来源](https://developers.cloudflare.com/cloudflare-challenges/concepts/how-challenges-work/)：WAF、速率限制、Bot 防护、DDoS 防护等都可能发起挑战。验证请求与被挑战请求的出口 IP 不一致可能导致循环。尚无证据确认 linux.do 对这些请求具体命中了哪条规则。
3. [验证有效期](https://developers.cloudflare.com/cloudflare-challenges/challenge-types/challenge-pages/challenge-passage/)：通过后签发的 `cf_clearance` 可以减少重复验证，有效期由站点设置；Challenge Passage 不豁免速率限制。不能假定 linux.do 使用官方默认有效期。
4. [浏览器兼容性](https://developers.cloudflare.com/cloudflare-challenges/reference/supported-browsers/)：普通主流浏览器受支持；嵌入式浏览器支持有限，自动化浏览器不属于生产挑战的受支持环境。因此当前 CDP 浏览器接续实现也不能承诺自动通过，需要继续观察兼容性，不能把一次成功当作永久解决。
5. [重复验证排查](https://developers.cloudflare.com/cloudflare-challenges/troubleshooting/challenge-solve-issues/)：不稳定连接、脚本被阻止、浏览器配置及代理等可能影响完成验证。此次未改动用户代理/VPN、未伪造指纹，也未自动点击验证控件。

## 后续优化优先级

- 已落实：合并重复读取、共享冷却、暂停后台重试、区分普通限流与挑战、保留验证会话，避免刷新时重置等待。
- 持续核查：通知轮询是否在后台页面仍过于频繁；首次启动、会话失效、网络切换时是否发生请求集中爆发；验证和后续 API 是否始终保持同一会话及网络路径。
- 诊断补齐：按传输通道统计总请求数、挑战次数和恢复结果，记录脱敏的接口分类及 Ray ID，才能比较改版前后的实际触发率。目前不能声称验证减少了某个百分比。
- 若常规浏览器仍持续挑战，需要凭 Ray ID 与站点维护者确认匹配规则和官方客户端/API 接入方式；客户端本身无法改变站点策略，也不能用自制小游戏替代站点认可的验证。

针对默认等待、并发、重复限流、取消刷新、后台请求、挑战响应、服务器长冷却和 OTP 登录的 19 项回归测试通过；Android release Kotlin 编译通过。测试使用模拟响应，不向生产站点制造限流或提交内容。

## Android 接入补充

用户确认 Android 也启用相同恢复策略后，提取 `NetworkRecoveryPolicy`，避免依赖 macOS 验证状态。Android WebView 的读取、CSRF 和上传响应会把 `Retry-After` 传回公共网络层，在完成等待回调之前写入冷却时间。关闭旧的 Android 429 内层重试，由公共协调器执行一次有等待的恢复；网络恢复事件与手动刷新均保留限流截止时间。上传与写操作仍不会因限流而自动重放。

Android 原有 Cloudflare WebView 验证生命周期保持独立，带挑战标记的响应不进入普通 429 自动重试。新增针对 Android 启用状态的并发、服务器等待时间、后台请求、挑战响应及并行成功响应测试；不以桌面编译代替安卓真机验证。

新增 5 项 Android 策略回归测试通过，与现有测试合计 24 项通过。Android release APK 构建通过。ADB 未检测到连接设备，因此尚未覆盖安装或进行三星真机验证。
